# HOLOMEDAI — PHASE F3.2 ARCHITECTURE
## M49 FIRST LIVE SLICE: FREEFORM SWEPT CUTTING

## 1. OBJECTIVE
Design the definitive live freeform cutting architecture for the HoloMedAI M49 milestone. F3.2 bridges the gap between raw hardware input (laptop camera) and the already sealed F2 SliceEngine, replacing the idealized planar cut with a mathematically rigorous SweptCutSurface derived from a tracked hand trajectory.

## 2. SCOPE & NON-GOALS
**Scope:**
- Deterministic SweptCutSurface generation from ProcessedCutTrajectory.
- Parallel-transport (Bishop) frame generation for 3D trajectory sweeping.
- Software-only camera capture and MediaPipe-based hand tracking boundaries.
- Hand-state-to-trajectory state machine.
- Strict integration with F1 (Authority/IPC), F2 (SliceEngine), and F3.1 (Deterministic Trajectory).
- Defensive Unity endpoint.

**Non-Goals:**
- Modifying the sealed F2 SliceEngine or F3.1 trajectory architecture.
- Real hardware (surgical tool) integration.
- Frame-by-frame LLM invocation (strictly forbidden).
- Presets, planar snapping, or gesture-to-preset mapping (strictly forbidden).
- Granting authority to Unity, camera, or MediaPipe.

## 4. MATHEMATICAL MODEL: SweptCutSurface CONTRACT
The `SweptCutSurface` represents a 3D ribbon generated by sweeping a 1D cross-section along the 3D trajectory centerline.

* **Centerline:** Derived exactly from `ProcessedCutTrajectory.samples`.
* **Parameterization:** $S(s, u) = C(s) + u \cdot W \cdot B(s)$, where:
  * $s \in [0, L]$ is the arc-length parameter.
  * $u \in [-0.5, 0.5]$ is the cross-section parameter.
  * $C(s)$ is the centerline coordinate.
  * $W$ is the scalar width of the cutter.
  * $B(s)$ is the binormal vector (transverse orientation).
* **Tangents:** Computed at each valid sample using central differences for internal points and forward/backward differences at boundaries.
* **Width & Thickness:** Inherited from the trajectory/tool definition. Cross-section is represented as a thickened line segment.
* **Start/End Behavior:** Flush/flat caps orthogonal to the tangent at $s=0$ and $s=L$.
* **Continuity:** The surface maintains $G^1$ orientation continuity outside of strictly preserved corner neighborhoods (which remain $C^0$).
* **Coordinates:** Strict Right-Handed (RH) canonical anatomical space. Units in meters.

## 5. FRAME TRANSPORT (BISHOP / PARALLEL TRANSPORT)
To define the orientation vectors—Normal $N(s)$ and Binormal $B(s)$—a Rotation-Minimizing Frame (Bishop Frame) is explicitly transported along the trajectory. 

**Transport Rule:**
Given a tangent $T_i$ and $T_{i+1}$, the rotation matrix $R_i$ that aligns $T_i$ to $T_{i+1}$ along the shortest great circle is computed using the axis-angle representation where the axis is $T_i \times T_{i+1}$.
* **Propagation:** $N_{i+1} = R_i N_i$ and $B_{i+1} = R_i B_i$.

**Edge Cases & Determinism:**
* **Initial Frame Ambiguity:** Established via the first valid tangent $T_0$ and a deterministic fallback vector (e.g., world UP $+Y$). If $T_0 \parallel +Y$, fallback to $+Z$.
* **Near-collinear / Straight trajectories:** The cross product approaches zero. Tolerances (e.g., $10^{-6}$) bypass rotation, directly copying the previous frame.
* **180° Tangent Reversal:** Treated as a degenerate failure condition. Halts surface generation safely.
* **Stationary/Zero-length:** Handled upstream by F3.1 resampling (duplicates are collapsed).

## 6. STRAIGHT TRAJECTORY SEMANTICS
A straight trajectory (highly collinear samples) fundamentally lacks intrinsic geometric curvature to uniquely lock a roll angle.
* **Rule:** Do NOT silently reinterpret a straight line as an arbitrary plane (e.g. strict axial plane).
* **Orientation Authority:** Derived strictly from the initial frame heuristic ($+Y$ reference) or explicitly supplied tool orientation (from hand interaction state).
* **UX Result:** A straight user stroke deterministically sweeps a flat ribbon oriented according to the initial fallback vector, functioning mathematically exactly like a curved trajectory that happens to have zero curvature.

## 7. FREEFORM GEOMETRY REQUIREMENT
Trajectories MUST remain strictly geometric and distinct. No trajectory may snap to a preset anatomical plane.
* **Equivalence Semantics:** Two surfaces are identical if and only if their centerlines and transported frames match within a strict floating-point tolerance ($10^{-5}$ meters).
* An L-shaped path, S-curve, straight line, and arbitrary 3D curve will generate uniquely mapped sweeping ribbons without post-classification mapping.

## 8. F3.1 → F3.2 CONTRACT
F3.2 consumes `ProcessedCutTrajectory`.
* **F3.1 Provides:** `samples` (Point3D), `timestamps` (float), `metadata` (immutable dict).
* **F3.2 Extends (if needed):** F3.2 expects F3.1 output to be perfectly sequential. Tangent computation and frame generation (which require width/thickness definitions) are strictly owned by F3.2. F3.1 remains purely positional and untouched.

## 9. F2 INTEGRATION BOUNDARY (ADAPTER)
F2 is SEALED and currently operates on planar half-space primitives and `CutSurface`.
* **Boundary:** An adapter will decompose the continuous `SweptCutSurface` into a sequence of micro-planar operations (or triangulated boolean meshes, depending on F2's exact topological ingress) that F2 can consume without invariant modification.
* **Rule:** If F2 expects explicit triangulated mesh boundaries for volume clipping, F3.2 will construct the watertight enclosing boundary of the swept ribbon to submit to F2 as a `SliceOperation`.

## 10. LIVE CAMERA BOUNDARY
* **CameraNode:** Standard OpenCV wrapper (`cv2.VideoCapture`). Maintains a strict depth-1 newest-frame buffer to prevent lag. Runs on a dedicated daemon thread.
* **Metadata:** Assigns deterministic frame ID and monotonically increasing capture timestamp.

## 11. MEDIAPIPE BOUNDARY
* **PerceptionNode:** Adapts MediaPipe Hands (Python Task API).
* **Interface:** Injectable interface. F3.2 math has NO direct dependency on MediaPipe imports.
* **Output:** Normalized 3D landmarks (`[0,1]` scale), scalar confidence, tracking status, handedness.

## 12. HAND INPUT TO TRAJECTORY (STATE MACHINE)
Maps perception output to deterministic intent.
* **States:** `NO_COMMAND` → `TRACKING` → `CUT_ACTIVE` → `HOLD` (Uncertainty) → `CUT_END`.
* **Transitions:** 
  * `TRACKING` → `CUT_ACTIVE`: Explicit interaction gesture (e.g., pinch + motion threshold).
  * `CUT_ACTIVE` → `HOLD`: Temporary tracking loss or low confidence (< 0.5) for less than 500ms.
  * `HOLD` → `CUT_END`: Sustained tracking loss > 500ms, or explicit end gesture.
  * `HOLD` → `CUT_ACTIVE`: Tracking restored gracefully.
* **Output:** A discrete `CutTrajectory` object is emitted only upon `CUT_END`. 

## 13. AUTHORITY BOUNDARY
* Perception and Hand-State machines are purely intent generators. They emit `CommandRequest`.
* **Rule:** They NEVER emit `AdmittedCommandCapability` or assert authority. 
* The existing M49/F1 `admission.py` architecture accepts the `CommandRequest`, validates isolation, and issues the capability.

## 14. UNITY SOFTWARE ENDPOINT & IPC BOUNDARY
* **Role:** Unity is a visual endpoint, a defensive verifier, and a source of simulation evidence. It is NOT authoritative.
* **IPC Transport:** WebSocket + JSON framing.
* **Payload:** JSON metadata encapsulating a Base64 encoded binary geometry blob (vertices/indices of the swept surface). Includes piece ID, version, and integrity hash.
* **Evidence:** Unity emits `DRIVER_ASSERTED_SOFTWARE_EVIDENCE`. It explicitly cannot claim physical hardware isolation.

## 15. FAILURE & RECOVERY SEMANTICS (FAIL-CLOSED)
* **Camera/MediaPipe Failure:** Hand state transitions to `NO_COMMAND` or `CANCEL`. Ongoing trajectory is discarded.
* **Degenerate Geometry (180° flip):** `TrajectoryValidationError` is raised. Operation halts before F2 admission.
* **Unity Disconnect:** Operation pauses; queue backpressure explicitly drops new visual updates rather than crashing the solver.
* **Authority Rejection:** Command fails cleanly, logging security telemetry.

## 16. DETERMINISM & PERFORMANCE BUDGETS
* **Determinism:** Identical sequences of hand landmarks MUST produce identical Base64 geometry blobs for Unity and identical volume operations in F2. Floating point tolerance enforced at $10^{-5}$. Ambiguous frame initialization is fully specified (Fallback $+Y$, then $+Z$).
* **Budgets (Target):**
  * Camera → Perception: ~16 ms
  * Intent State Machine: ~2 ms
  * F3.1 + F3.2 Swept Gen: < 10 ms
  * IPC Transmission: < 10 ms
  * Motion-to-photon: < 100 ms

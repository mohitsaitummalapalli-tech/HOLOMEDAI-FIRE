# M49 FIRST LIVE SLICE - PHASE F3.2-D ARCHITECTURE
## FREEFORM F2 EXTENSION ARCHITECTURE

### 1. REASON FOR STOP & CURRENT F2 LIMITATIONS
During the F3.2-D integration audit, it was correctly identified that the sealed F2 `SliceEngine` is mathematically and architecturally hardcoded to support ONLY planar geometry. 
The exact limitations are:
- **Type Rejection:** `SliceEngine.slice_piece` enforces `isinstance(operation.cut_surface, PlanarCutSurface)`.
- **Scalar Classification:** Slicing relies on `_distance_to_plane`, reducing inside/outside classification to a single scalar dot product against a constant infinite normal.
- **2D Capping:** `_cap_mesh` uses `_triangulate_polygon`, which explicitly projects 3D intersection boundary loops onto a 2D plane defined by the constant normal, followed by 2D ear clipping.

Attempting to coerce a `SweptCutMesh` (a bounded, non-planar 3D manifold) into this engine without architectural modification would require either silent fallback to a planar approximation (violating the core freeform requirement) or mathematically invalid 2D projection of 3D loops (resulting in broken, self-intersecting topological caps).

### 2. ARCHITECTURAL OBJECTIVE
The objective of F3.2-D is to implement the smallest mathematically rigorous architectural extension to the existing F2 slicing engine that natively supports `SweptCutSurface` bounded freeform cutting. This extension MUST:
1. Preserve the existing `PlanarCutSurface` strategy and exact numerical behavior.
2. Produce two finite, valid, watertight `AnatomicalPiece` children from a freeform cut.
3. Be purely deterministic, avoiding object identity or hash-based ordering.
4. Fail closed on unsupported topologies or geometric degeneracies.

### 3. CANDIDATE STRATEGIES

#### OPTION A: ZERO-THICKNESS SURFACE INTERSECTION & CUTTER-GRAFTING
- **Concept:** The `SweptCutMesh` is treated as a zero-thickness mathematical boundary. Target mesh triangles are intersected against cutter triangles. The resulting intersection lines form closed 3D loops. 
- **Capping:** Because the `SweptCutMesh` is itself a valid triangulated mesh, the cap is generated by extracting the sub-mesh of the cutter that lies *inside* the intersection loop. This "cutter-grafting" perfectly preserves the freeform shape without complex 3D Delaunay triangulation.
- **Pros:** Exact freeform preservation, deterministic, avoids general 3D constrained triangulation, mathematically elegant.
- **Cons:** Requires robust edge-triangle intersection and planar/coplanar edge handling.

#### OPTION B: CLOSED CUTTER VOLUME (BOOLEAN CSG)
- **Concept:** The `SweptCutSurface` is extruded using its `thickness` semantics into a closed 3D volume. Slicing becomes a classic 3D Boolean mesh operation (Target MINUS Volume).
- **Pros:** Conceptually standard (CSG).
- **Cons:** A true 3D Boolean engine is highly complex, prone to numerical instability, and over-complicates a simple surgical slice. It effectively "deletes" material (a volumetric kerf), which violates the F2 expectation of a pure mathematical split without volume loss.

#### OPTION C: SIGNED DISTANCE FIELD (SDF) VOXELIZATION
- **Concept:** Convert target and cutter to volumetric SDFs, perform voxel-based split, and use Marching Cubes to reconstruct.
- **Pros:** Robust against topological errors and self-intersections.
- **Cons:** Destroys original mesh geometry, introduces voxel quantization artifacts, not exact, highly computationally expensive.

### 4. SELECTED STRATEGY: OPTION A (CUTTER-GRAFTING)
Option A is selected. It strictly honors the zero-thickness mathematical boundary of the `SweptCutMesh`. 

#### Mathematical Model
1. **Target:** Closed 2-manifold triangle mesh $M$.
2. **Cutter:** Bounded open 2-manifold triangle mesh $C$.
3. **Intersection:** $M \cap C$ produces a set of 3D boundary loops $L$.
4. **Classification:** $M$ is split into $M_{front}$ and $M_{back}$ based on a localized flood-fill or ray-cast classification from $C$.
5. **Capping:** The subset of $C$ bounded by $L$, denoted $C_{cap}$, is extracted. $M_{front}$ is capped with $C_{cap}$ (inverted normals). $M_{back}$ is capped with $C_{cap}$ (original normals).

#### Cutter Representation
The freeform slice engine consumes the `SweptCutMesh` generated in F3.2-C. Thickness is ignored for the zero-thickness slice operation (thickness remains reserved for future physical extrusion/collision semantics).

#### Topology Constraints & Self-Intersection
- The first implementation (F3.2-D) explicitly **supports only cuts that completely bisect the target mesh** or enter/exit cleanly.
- Partial cuts (cutter stops inside target) are UNSUPPORTED and MUST fail closed.
- Self-intersecting `SweptCutMesh` inputs are UNSUPPORTED and MUST fail closed.
- Invalid intersections (e.g., non-closed boundary loops) MUST fail closed.

#### Determinism & Tolerances
- **Tolerances:** The existing `COORDINATE_EPSILON` ($1e-6$ m) applies to vertex welding and point-on-surface evaluations. 
- **Determinism:** All boundary loops, face sets, and vertex indices must be sorted by standard XYZ tuple comparisons. No Python `set()` iteration or `id()` memory addresses may dictate mesh generation order.

#### Failure Semantics
- Any failure in finding closed loops, non-manifold geometry, zero-area faces, or volume conservation violations will trigger an `AnatomyValidationError`.
- No silent fallback to planar slicing. 

### 5. F2 PRESERVATION: SLICE STRATEGY BOUNDARY
The F2 engine will be modified with a safe architectural pattern:
```python
class SliceStrategy(ABC):
    @abstractmethod
    def slice(self, mesh: AnatomicalMesh, surface: CutSurface) -> Tuple[AnatomicalMesh, AnatomicalMesh]: ...

class PlanarSliceStrategy(SliceStrategy): ... # Exact sealed F2 logic
class FreeformSliceStrategy(SliceStrategy): ... # New Option A logic
```
`SliceEngine` will act as a factory/dispatcher. If `PlanarCutSurface` is passed, `PlanarSliceStrategy` executes, ensuring 100% mathematical bit-for-bit regression preservation.

## 2. Prove RELEASE/CANCEL are NOT ordinary command admission

By design, ACTION_RELEASE and ACTION_CANCEL completely bypass the ordinary command admission pipeline.

* **Cannot create a second physical operation:** They invoke preempt_by_correlation, which delegates to preempt_execution. preempt_execution uses the *existing* execution_id (manager.py:954) instead of minting a new one.
* **Cannot create a command nonce:** No envelope is created by the CycleCoordinator for these intents (cycle.py:97-99 has no call to create_envelope_from_proposal).
* **Cannot mint a physical_operation_id or EndpointLease:** The preempt_execution method (manager.py:981) does not call _capacity_admitter. It only requests 	arget_endpoint.request_stop(execution_id) (manager.py:1044) or terminates the operation early (manager.py:1045).
* **Cannot invoke ordinary handle_command():** The CycleCoordinator strictly calls dcm.preempt_by_correlation(intent.correlation_id) and does not enter the elif intent.action == ACTION_GRASP branch (cycle.py:97).
* **Cannot bypass ResolutionGate:** preempt_execution explicitly checks self._resolution_gate.route_stop_request (manager.py:1041) before invoking device stop.
* **Cannot bypass durable binding:** preempt_by_correlation enforces exact match via _capacity_snapshot_provider (manager.py:939). If the execution isn't actively leased, it fails or no-ops.
* **Targets the original E1 binding:** The device_id and endpoint_id are derived from the active operation payload (manager.py:956-960), guaranteeing it hits the correct device and session without arbitrary overwrite.

## 3. Audit the new CycleCoordinator bridge

The CycleCoordinator (Phase 4.5 in python/holomed/platform/cycle.py:81-112) maintains its strict boundary as an orchestrator.

* **Consumes proposals only:** Only UltronProposal objects are consumed via _proposer.process_intent(intent, target_device) (cycle.py:101).
* **Does not become authority:** It invokes dcm.handle_command or dcm.preempt_by_correlation. It never directly interacts with devices or internal registry persistence.
* **Does not construct EndpointLease or manufacture physical identity:** MessageEnvelope construction provides a UUID execution_id and command_nonce (cycle.py:108-109), but the actual authoritative physical_operation_id and EndpointLease are strictly minted inside DeviceControlManager.admit_physical_command().
* **Does not maintain a hidden execution map or lifecycle store:** All routing dynamically relies on the stateless intent evaluation and DeviceControlManager lookups.
* **Does not bypass DCM admission:** All GRASP commands go through handle_command(envelope) (cycle.py:111).
* **Does not use fire-and-forget async execution:** The execution is synchronous in the Python bridge environment (cycle.py:111).
* **Error handling:** If handle_command returns an ERROR envelope, the CycleCoordinator ignores it since admission failed, correctly averting false positive success reporting.

## 4. Audit IntentDetector correlation lifecycle

The IntentDetector enforces correlation ID integrity and temporal consistency.

* **FORMING → STABLE_GRASP:** Emits exactly one ACTION_GRASP intent with a newly stable correlation_id (intent.py:408).
* **STABLE_GRASP → RELEASE:** If confidence falls below threshold (intent.py:440), emits exactly one ACTION_RELEASE intent using the *same* correlation ID, then immediately clears self._current_correlation_id = None (intent.py:448).
* **STABLE_GRASP → sustained tracking loss:** If transient failures exceed max allowed (intent.py:358), emits exactly one ACTION_CANCEL using the *same* correlation ID, then clears it (intent.py:432).
* **RELEASE/CANCEL emission:** As seen above, correlation state is unequivocally cleared immediately after emission.
* **Next interaction:** After state resets to NO_COMMAND, any new FORMING → STABLE_GRASP edge will accept the new correlation_id from the perception payload and begin a fresh sequence.
